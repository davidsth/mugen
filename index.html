01 — THE PROBLEM

The URL was never a good address.

On the web, an address says where to go — then you trust DNS, a domain owner, and a chain of certificate authorities that you actually arrived at the right place. Mugen flips it: identity first, location second.

The web today

Location is identity — and location can be taken.

  • ✕

    You type the address. One wrong letter is a typosquat, a lookalike, a phishing page.

  • ✕

    Domains expire and change hands. The app you trusted yesterday can be someone else's server tomorrow.

  • ✕

    Every page runs foreign code. Scripts, trackers, and third parties execute inside your browser.

  • ✕

    Ads and popups fight for your attention. Banners, modals, cookie walls, autoplay — the page serves advertisers first.

  • ✕

    A new account for every site. Another password, another profile to fill in, another inbox of “verify your email.”

  • ✕

    Accessibility is bolted on — if at all. Screen readers guess at divs; keyboard users get trapped in custom widgets.

  • ✕

    Moving hosts breaks everything. New domain, new login, lost data, dead links.

With Mugen

Identity is a key. The server address is just a hint.

  • ✓

    You join apps, you don't visit addresses. Discover, preview the publisher and permissions, join in one tap.

  • ✓

    The key can't be hijacked. A taken-over domain still can't sign as the app — the client refuses to render it.

  • ✓

    Apps never run code on your machine. They send a validated UI tree. Mugen lays it out and paints it — so there's nothing to inject an ad or a popup with.

  • ✓

    One profile signs you in everywhere. Join once, and every app knows your name, avatar, and preferences — shared only with your permission.

  • ✓

    Accessibility is in the tree itself. Every node carries a real role and label, so screen readers and keyboards work in every app, automatically.

  • ✓

    Creators can move freely. New server, same signed identity, same storage and login for you.

02 — CORE PRINCIPLES

Built in, not bolted on.

These aren't settings you hunt for or extensions you install. They're consequences of how Mugen is built — apps send a validated UI tree, and the Rust client decides what can ever appear on your screen.

✕ ads

Ad & popup free — structurally

There is no ad slot, no modal-on-a-timer, no cookie wall, and no third-party script that could spawn one. An app can only place the nodes it declares, inside its own window, and the shell owns every dialog. Nothing can interrupt you from outside the app you're using.

NO AD NODES · NO POPUP API · NO THIRD-PARTY SCRIPTS · SHELL OWNS ALL DIALOGS
1

One account. One profile. Every app.

No new password per app, no profile form for the hundredth time. You create one Mugen profile; joining an app shares only what you approve — name, avatar, contact — and sign-in is the same key-backed identity everywhere.

0 KB

No JavaScript bloat

Webpages ship megabytes of JS before they show anything — frameworks, trackers, hydration. Mugen apps ship no JavaScript at all: the server sends a small binary patch of what changed, and the native client — installed once — does the rendering. Updates are kilobytes, not bundles.

0 JS DOWNLOADED PER APP · BINARY PATCHES, NOT BUNDLES · NO TRACKERS TO LOAD
a11y

Accessibility first

Because apps are semantic trees — Button, Input, List, Text — not pixels or divs, Mugen builds a real accessibility tree (via AccessKit) for every app for free. Screen-reader labels, full keyboard navigation, focus you can see, high-contrast theming, and reduced-motion support come from the client, so no app can forget them.

SEMANTIC NODES · SCREEN READER + KEYBOARD IN EVERY APP · CONTRAST & MOTION FROM THE SHELL
∞

As rich as any webpage

Virtualised lists scroll through thousands of products or posts, Canvas and Video cover dashboards, editors, and media, and grids + stacks compose storefronts, booking flows, and workspaces. 03 — HOW IT WORKS

Creators host. Mugen renders.

The split is the whole design. Crystal apps stay on their creators' servers, owning logic and data. The Rust client owns the window, the layout, and every pixel — and nothing else needs to be trusted.

一

Build in Crystal

Write components with the Mugen SDK. They describe UI as a tree — not pages, not markup.

sdk/crystal
二

Publish a manifest

Sign your app's name, icon, version, permissions, and server endpoints with your publisher key.

manifest · signed
三

People join

Your app appears in the directory. Joining pins your key and approves your permissions — before anything renders.

directory → joined list
四

Mugen verifies & renders

The client checks the server proves your key, receives a UI snapshot, and paints it with its own engine.

snapshot → pixels
五

Events up, patches down

Taps and typing travel back as events. The server replies with small tree patches — never a full reload.

event ⇄ patch

Crystal app — creator's server

Logic, data, routing, and who can do what.

  • Components → UI tree
  • Diffs tree → patch
  • Handles events
⇄

The protocol

Binary, versioned, validated hard in Rust.

  • Snapshot on connect
  • Patch per change
  • Event per interaction
→

Rust client — your machine

Shell, layout, and rendering. No app code ever runs here.

  • winit window + input
  • Constraint layout, dirty tracking
  • wgpu display list + text atlas
04 — FOR CREATORS

Write Crystal. Ship an app, not a website.

No frontend bundle, no browser quirks, no CSS. You write components on your server; every joined client renders them natively and stays in sync through patches.

# apps/tasks/src/tasks.cr
component TaskList do
  column(gap: 8) do
    text "Today", size: 18, weight: :bold

    list(tasks) do |task|
      row do
        checkbox(task.done?,
          on_toggle: ->toggle(task))
        text task.title
      end
    end

    input(placeholder: "Add a task…",
      on_submit: ->add_task)
  end
end

The SDK compiles this to typed nodes, diffs against the last tree, and sends only what changed. Style is typed too — enums and tokens, never strings of CSS.

A — YOUR SERVER, YOUR RULES

You host it, you own the data

Apps run where you put them — a VPS, a home server, anywhere. Change hosts anytime; your signed manifest points clients to the new endpoint and your identity doesn't change.

B — ONE REPO, NO DRIFT

Client, protocol, and SDK grow together — planned layout

C — A SMALL, HONEST SURFACE

Ten node types are enough — for complex apps

Box, Text, Image, Scroll, Stack, Input, Button, List, Canvas, Video. Composed, they build the complex things webpages do today: storefronts with carts and checkout, travel planners with maps and itineraries, media feeds, dashboards, and editors. A small surface is what keeps every one of them consistent, accessible, ad-free, and unable to draw outside the lines — or pop anything up over another app.

You verify before you render.

On the web you click a link and you're already on someone's page. In Mugen, joining starts with a preview: who made this, what it wants, and the fingerprint of the key that proves it.

The address behind this card can change. This key can't be faked.

  • ✓

    Lookalikes get caught

    A new app with a familiar name but a different key is flagged as a lookalike — and its key-derived mark won't match the one you know.

  • ✓

    Nothing leaks between apps

    No cookies, no third-party scripts, no referrer. Storage and sign-in are isolated per app ID, brokered by the shell.

  • ✓

    Updates can't be smuggled in

    Updates are signed manifests with rising version numbers. Unsigned updates and downgrades are refused.

  • ✓

    The directory can't impersonate

    The directory is for discovery — search, categories, plain-language permissions. Even a compromised directory can't fake an app without its private key. You can always join directly by invite.

  • ✓

    Bad apps can't hurt the client

    Every tree is validated: max depth, max nodes, max text, no duplicate IDs. Unknown nodes are ignored — never a crash, never a frozen window.

07 — START BUILDING

Clone it on macOS. Open it in VS Code.

Mugen is developed on macOS — where wgpu targets Metal — with VS Code as the editor. The repo is public; the layout in the For Creators section is the planned structure, and the build starts with the protocol crate and an empty shell window.

# clone the repo
$ git clone git@github.com:davidsth/mugen.git
$ cd mugen

# check your toolchains
$ rustc --version && cargo --version
$ crystal --version

# goal for the first milestone, once the
# shell crate lands: an empty window that
# opens and closes cleanly
$ cargo run -p shell
